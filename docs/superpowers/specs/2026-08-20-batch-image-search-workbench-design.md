# Temu 批量图搜工作台设计

## 目标

把现有 GitHub Pages 原型改造成可实际使用的批量图搜工作台。用户可批量上传本地图片或粘贴图片链接；本机任务服务把每张图片串行提交给 VMOS 中的 Temu App，并从已验证的 `Um.g.d` 内存集合读取 20 个商品；网页持续展示单图进度和分组商品结果。

首版仅供当前电脑使用，同时保留 GitHub Pages 入口。后续可把同一 API 通过 HTTPS 域名反向映射，无需改写前端业务协议。

## 视觉约束

现有线上页面 `https://kingf668877-creator.github.io/temu-image-search/` 是实现基准。必须保留当前页面的配色、字体、导航、首屏、上传区域、标签页、按钮、间距、圆角、卡片风格、响应式断点和整体视觉层级；不得按独立草图重做样式，不引入新的 UI 框架，不替换 `css/style.css` 的视觉体系。

新增功能只在现有 DOM 和 CSS 组件语言内扩展：复用已有预览区、结果区、分页、按钮、状态标签和商品卡片。需要增加源图队列时，应把它作为现有结果区域的内部子布局，并使用当前颜色变量、边框、阴影和排版。现有文案仅在与真实实现冲突时校正，例如把 CDP/TLS 离线解析改为 VMOS App 与 `Um.g.d` 内存模型导出；不改变品牌名称和页面结构。

## 范围

首版包含图片文件批量上传、图片链接批量提交、任务队列、单图状态、失败重试、每张源图的商品卡片、当前图和整批 JSON/CSV 导出。本版不实现账号系统、多用户隔离、多台云手机并行、长期数据库和付费功能；表格上传保留入口但不作为首版验收项。

## 端口与进程隔离

新服务默认只监听 `127.0.0.1:15443`，通过 `PORT` 环境变量覆盖。不得停止、占用或修改当前电脑上的 `5000`、`5443`、`9225` 服务。ADB 和 Frida 沿用已验证的独立隧道；启动前检查端口占用，若 `15443` 已被占用则退出并提示用户显式选择新端口，不自动杀进程。

本地页面从同源 `/api` 调用服务。线上页面默认通过 `https://yidong.dianleida.net:21998` 调用服务，也可使用 `window.TEMU_BACKEND` 覆盖；前端先执行健康检查，无法连接时显示服务未启动或浏览器安全策略阻止访问，而不是无限轮询。

## 系统边界

### 网页前端

前端负责选择文件、解析链接、校验批次、提交任务、展示进度、切换源图结果、重试失败项和导出数据。前端不保存 VMOS 密钥、不直接调用 ADB/Frida，也不解释原始 Java 对象。

在现有结果区域内增加源图任务列表，展示缩略图、名称、状态、排队位置、耗时、结果数和错误原因；选中任一源图后，原有商品网格展示该图的 20 个结果。桌面端可并排显示，窄屏沿用当前响应式规则改为上下布局。

### 本地任务服务

服务接收本地文件和远程图片链接，把每张图片标准化为独立任务项，按先进先出顺序交给单一执行器。任务状态保存在内存并周期性落盘为 JSON，以便服务重启后保留已完成结果；上传临时文件在批次完成后按保留策略清理。

### VMOS 执行器

执行器一次只处理一张图片：准备图片、推送到 Android 媒体目录、触发媒体扫描、打开 Temu 图搜、在系统选择器选中图片、等待结果页并严格验证。验证条件包含图搜标题、商品卡片、无活动文字搜索框、无搜索建议，并记录截图或 XML 作为失败诊断证据。

验证成功后附加轻量 Frida Agent，通过 `BGProductListView → RecyclerView.E → Lm.d.f0 → Um.g.d` 读取商品集合。禁止恢复会拖慢 Cronet 的全局 `ByteBuffer.flip()` Hook，也不使用仓库原有的 CDP/TLS 猜测接口。

## 数据流

1. 用户选择多张图片或粘贴多条 URL。
2. 前端生成稳定的客户端项 ID，预览并去重。
3. 前端创建批次，文件使用 multipart 上传，链接使用 JSON 提交。
4. 服务返回批次 ID和所有项的初始状态。
5. 队列逐项执行图搜；状态变化通过轮询接口返回，首版轮询间隔 1.5 秒。
6. 单项成功后立即保存结果，前端无需等待整批完成即可查看。
7. 单项失败只标记该项，不中断后续图片；用户可单独重试。
8. 整批完成后保留成功与失败摘要，并允许导出。

## API 约定

- `GET /api/health`：返回服务版本、端口、ADB/Frida/Temu 会话状态和当前队列长度。
- `POST /api/batches/files`：创建文件批次，字段名为 `images`，首版每批最多 100 张，单张最多 4 MB。
- `POST /api/batches/urls`：创建链接批次，接收 `urls: string[]`，每批最多 100 条。
- `GET /api/batches/:batchId`：返回批次摘要、所有项状态和已完成项的结果摘要。
- `GET /api/batches/:batchId/items/:itemId`：返回单张图片的完整商品结果。
- `POST /api/batches/:batchId/items/:itemId/retry`：只重试失败项。
- `GET /api/batches/:batchId/export?format=json|csv`：导出整批数据。

状态枚举为 `queued`、`preparing`、`searching`、`extracting`、`succeeded`、`failed`、`cancelled`。服务返回稳定错误码以及可读中文信息，前端不根据异常字符串猜测状态。

生产响应删除 `_class` 和 Android 展示字段，保留：

## URL 输入安全

服务只接受 `http` 和 `https` 图片链接，限制响应大小、下载超时、重定向次数和 MIME 类型。必须拒绝回环地址、私网地址、链路本地地址以及解析后落入这些网段的域名，防止通过图片 URL 访问本机内部服务。上传文件按内容检测图片类型，不信任扩展名。

GitHub Pages 来源和本地来源使用明确的 CORS 白名单。服务默认绑定回环地址，不向局域网暴露；未来域名映射时再增加鉴权、请求限流、HTTPS 和持久化存储。

## 界面行为

上传区保留文件和链接两个入口及当前交互样式。提交后在现有结果区显示任务列表和商品网格；选择任一成功项会更新商品网格。商品卡片沿用现有 `.result-card`、`.result-thumb`、`.result-body` 和操作按钮样式，展示主图、两行标题、售价、划线价、销量、折扣、广告标签和打开商品按钮。缺失值不显示虚假的“0 分”或“待定评分”。

批次顶部展示完成数、总数、当前项和估算剩余时间。首版基于最近完成项的移动平均计算 ETA；没有样本时按每张 60 秒估算，不承诺固定完成时间。页面刷新后可凭本地保存的批次 ID恢复进度。

## 错误处理

图片下载、ADB 离线、选图失败、Temu 网络错误、页面验证失败、Frida 附加失败、模型链路变化和商品数量异常分别使用独立错误码。每项最多自动重试一次；网络错误采用短暂退避，结构变化不自动重试。失败结果保存阶段、错误码、文字说明和诊断文件路径，但不向浏览器暴露本机绝对路径或认证信息。

如果导出集合不是 20 条，服务保留实际数据并标记 `partial`，前端醒目展示结果不完整。不得用首页商品、文字搜索结果或详情页补采来凑满数量。

## 验收标准

- 新服务在 `15443` 启动，现有 `5000`、`5443`、`9225` 进程持续运行。
- 线上页面的视觉回归截图与改动前保持一致；只允许结果区因新增业务状态产生结构变化。
- 本地页面和 GitHub Pages 都能完成健康检查、提交批次和查看结果。
- 一批至少 3 张本地图片可串行处理，单项完成后立即可查看其商品。
- 每个成功项展示来自 `Um.g.d` 的商品，正常情况下为 20 条，并带 `image_search_result` 证据。
- 单项失败不阻塞后续项，失败项可单独重试。
- 商品卡片正确显示标题、主图、价格、销量和链接；空评分不显示为 0 分。
- JSON 和 CSV 导出按源图片分组，包含成功和失败摘要。
- 服务不包含 VMOS 密钥，诊断响应不泄露本机绝对路径。
- 桌面与移动端无横向溢出，长标题、长 URL 和错误信息不会覆盖控件。

## 测试策略

任务队列、字段归一化、URL 安全校验、状态迁移和导出分别编写单元测试。API 使用模拟执行器验证批次提交、进度更新、单项失败隔离和重试。真实设备验收使用三张已知图片完成端到端测试，并记录每张耗时、结果数量和字段覆盖率。前端在桌面和移动视口检查上传、队列切换、失败状态和商品网格，并把当前线上页面截图作为视觉回归基准。
